# 全员评审 / 签收 / 联调 执行顺序（发群版）

> 仓库：`admin/origin`（`http://192.168.50.25:3010`）  
> 目标分支：`develop`；所有功能经 PR 合并，**任何人不自行合并自己的 PR**  
> 三个词的含义：  
> **评审** = 看对方 PR，提意见；**签收** = 对方改完后你复评「通过，可对接」；**联调** = 真实环境把接口跑通  
> 核心原则：**评审可并行；签收按依赖；谁签收完就立刻和谁联调；不等全员到齐。**

## 三、常见误区（群内统一认识）

| 误区 | 正确 |
|------|------|
| 全队排队先审完成员1，再审4，再审5… | 评审可并行；成员1 的重点是**环境就绪**，不是被全员深度评审 |
| 所有人都要对每个人评审签收 | **谁依赖谁，谁主审谁**；无依赖关系的可只粗看或不看 |
| 「4、5之间联调」是主线 | 主线是 **成员6↔4**、**成员6↔5** |
| 等所有人签收完再统一联调 | 谁被签收完，**立刻**和依赖方联调 |
| 成员7 没好，全队等 | 成员7 只影响标准问答支路，不阻塞检索/CHAT 主链路 |
| 自己点 Merge | 一律由组长（成员1）在关键签收+联调完成后合并 |
